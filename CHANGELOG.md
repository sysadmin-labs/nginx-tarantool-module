# Changelog

## 2.8.1

First release from this repository, carrying on from upstream's v2.7.1. It
continues Tarantool's module, whose history is intact here; their
repository has had no commit since March 2021.

This replaces 2.8.0, whose archive still carried the Python test tree and
`misc/` that the repository had already dropped.

### Fixed

- **The version the module reported was a release behind.**
  `src/ngx_http_tnt_version.h` said v2.7.2. It was generated by a
  Makefile that upstream had, this repository does not, and nothing
  substituted it any more, so the value simply froze -- while
  `ngx_http_tnt_module` writes it to the error log at every
  configuration pass, which makes it the version anybody reading that
  log believes. `src/ngx_http_tnt_version.h.in`, the template with
  `@VERSION_STRING@` in it, went with the generator. `ci/version.sh`
  holds the header against `CHANGELOG.md` in the lint workflow now.

### Changed

- **yajl and msgpuck come from the system, always.** Upstream carried both
  as git submodules and preferred the bundled static libraries whenever
  they happened to be built. A release tarball never contains a submodule,
  so that path was only ever taken by someone building from a full clone,
  while every distribution — the FreeBSD port included — linked the system
  libraries. The submodules are gone and so is the second code path.
- `config` uses the `auto/module` form only, and refuses the build with a
  readable message when the two libraries are missing instead of failing
  later in the compile.
- `third_party/tp.h` moved to `src/`, which is the only file of that
  directory that was ever there.
- Dockerfile, docker-compose.yml, the top-level Makefile and the two
  example nginx.conf files are gone.

- Three one-bit bit-fields are unsigned now. As `ngx_int_t` they could
  not hold the 1 that was assigned to them -- it became -1 -- which clang
  refuses under `-Werror` and which is why the module did not build on
  FreeBSD at all. Every read is a truth test, so the behaviour was the
  same either way; a later `== 1` would not have been.

- The sanitizer workflow builds with `-DNGX_DEBUG_PALLOC=1` and collects
  the reports through `log_path`. nginx redirects its own stderr onto the
  error log file as soon as `error_log` names one, and Test::Nginx always
  names one, so reports written to stderr were lost: ASan was noticed
  only through the worker dying, and UBSan not at all.

### Added

- Continuous integration against nginx 1.28, 1.30 and 1.31, statically and
  dynamically, with sanitizers, valgrind, CodeQL and a FreeBSD run.
- `ci/version.sh`, run by the lint workflow.
- `ci/msgpuck.sh`, which builds msgpuck from a pinned commit where no
  package exists. FreeBSD has `devel/msgpuck` and builds nothing.
- `t/00-directives.t` for what the directives accept and refuse, and that
  an unreachable database fails rather than taking the worker down.
